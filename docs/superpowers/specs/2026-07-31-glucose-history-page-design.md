# Loop 首页血糖历史页面设计

## 目标

在 Loop 首页增加一个快速入口，用于查看最近 6 小时、12 小时或 24 小时的血糖图表和明细。

该页面解决以下问题：

- 首页现有曲线主要服务于当前状态和预测，不能方便地查看更长时间范围。
- MicroTech LinX 直接连接能够读取历史补包，但用户缺少独立的历史查看页面。
- 历史数据已经写入 Loop，页面应读取同一份数据，不能在 MicroTech 插件中重复保存。

## 已确认方案

1. 入口放在 Loop 首页。
2. 首页状态区下方增加独立的血糖历史入口行。
3. 历史页面顶部使用 `6 小时 / 12 小时 / 24 小时` 三个 Tab。
4. 默认选择最近 6 小时。
5. 页面上半部分显示血糖图表，下半部分显示按时间倒序排列的血糖明细。
6. 数据来源为 Loop 已保存的 `GlucoseStore`。
7. 页面适用于所有 CGM；MicroTech LinX 直接连接可以通过历史补包补齐数据。

## 非目标

- 不从历史页面直接连接或控制 CGM。
- 不在历史页面发起 MicroTech 历史请求。
- 不修改血糖入库、去重、治疗计算、告警或闭环逻辑。
- 不在 MicroTech 状态中另外保存一份 24 小时历史。
- 不修改首页现有 Glucose 曲线点击后的预测页面行为。
- 不为广播模式增加历史读取能力。

## 首页入口

入口位于 `StatusTableViewController` 首页状态区下方、现有曲线区域上方，作为独立的紧凑入口行。入口使用系统历史图表图标、`Glucose History` 标题和向右箭头。

行为：

- 当前已配置 CGM 时显示；没有配置 CGM 时隐藏。
- 整行可点击，触控高度不小于 44 点。
- 点击后通过现有导航栈进入 `Glucose History` 页面；历史页面显示导航栏和系统返回按钮。
- 保留底部已有进餐、预设模式、Bolus、运动和设置按钮，不增加第六个底部按钮。
- 入口提供本地化标题、`Glucose History` accessibility label 和稳定的 accessibility identifier。

选择独立入口行的原因：

- 首页当前隐藏系统导航栏，导航栏按钮无法显示。
- 首页 Glucose 曲线当前已经承担预测页面入口，不能替换其点击行为。
- 不修改共用 `ChartTableViewCell`，避免影响其它图表。
- 底部工具栏已有五个固定操作，继续增加按钮会压缩触控区域。

## 历史页面

页面使用 SwiftUI 实现，由 `StatusTableViewController` 推入一个 `UIHostingController`。页面标题为本地化的 `Glucose History`。

页面结构：

1. 顶部为固定的 segmented control：
   - `6 Hours`
   - `12 Hours`
   - `24 Hours`
2. 中部为血糖图表。
3. 下部为血糖明细列表。

默认行为：

- 首次进入默认选择 `6 Hours`。
- 切换 Tab 后立即查询对应时间范围。
- 图表按时间正序绘制。
- 明细按时间倒序显示，最新血糖在最上方。
- 页面不提供删除或修改血糖操作。

## 图表

图表复用项目现有 `PredictedGlucoseChart` 和 `ChartsManager`：

- 只设置实际血糖点。
- 预测血糖数组保持为空。
- 实际血糖沿用 Loop 现有散点样式，不把实际值伪装成预测值，也不额外连接跨越缺失时段的数据。
- 使用当前 `DisplayGlucosePreference` 单位。
- 横轴严格覆盖所选的 6、12 或 24 小时。
- 纵轴沿用 Loop 现有血糖显示范围和颜色规则。
- 图表容器使用稳定高度，不因数据量变化造成页面跳动。

现有 `ChartsManager` 固定使用一小时间隔生成横轴标签，直接显示 24 小时会造成标签重叠。为 `ChartsManager` 增加带默认值的一项横轴标签间隔配置，现有页面继续使用默认的一小时，历史页面按范围使用：

| 范围 | 横轴标签间隔 |
|---|---|
| 6 小时 | 1 小时 |
| 12 小时 | 2 小时 |
| 24 小时 | 4 小时 |

不新增另一套绘图库，也不手写血糖图表绘制逻辑。

## 明细列表

每行显示：

- 血糖时间。
- 按当前单位格式化的血糖值。
- 有趋势信息时显示趋势箭头。
- 用户手动输入的数据使用现有显示标识区分。

列表规则：

- 数据按 `startDate` 倒序。
- 原样展示 `GlucoseStore` 返回的持久化结果，页面不根据时间、`uuid` 或 `syncIdentifier` 再次去重。
- 6、12、24 小时均以当前时间为结束时间。
- 页面刷新时保持当前选中的时间范围。

## 数据来源

页面直接使用 `DeviceDataManager.glucoseStore`。

查询接口：

```swift
glucoseStore.getGlucoseSamples(
    start: now.addingTimeInterval(-selectedRange.duration),
    end: now
)
```

数据流：

1. MicroTech LinX 直接连接收到当前包或历史包。
2. `MicroTechCGMManager` 生成 `NewGlucoseSample`。
3. `DeviceDataManager` 按现有流程写入 `GlucoseStore`。
4. 历史页面从 `GlucoseStore` 查询同一份 `StoredGlucoseSample`。
5. 页面将查询结果同时交给图表和明细列表。

这样不需要修改 MicroTech 插件的数据所有权，也不会出现插件历史与 Loop 历史不一致。

## 页面模型

新增只负责历史页面的 `GlucoseHistoryViewModel`：

- 注入一个只包含历史查询函数的 loader，生产环境调用 `GlucoseStore.getGlucoseSamples`，单元测试注入可控结果，不重复定义完整 store 接口。
- 注入当前时间函数，生产环境使用 `Date()`，测试使用固定时间。
- 保存当前范围、加载状态、查询结果和错误状态。
- 将查询结果转换为图表使用的正序数据和列表使用的倒序数据。
- 每次切换范围生成新的查询标识，忽略较早查询的迟到结果。
- 所有页面状态更新回到主队列。

`GlucoseHistoryView` 通过现有 `DisplayGlucosePreference` environment object 读取单位，因此单位变化会立即更新图表和明细文本。

时间范围使用单一枚举作为权威来源：

```swift
enum GlucoseHistoryRange {
    case sixHours
    case twelveHours
    case twentyFourHours
}
```

枚举同时提供显示标题和时间长度，避免页面与查询逻辑各自维护常量。

## 自动刷新

页面在以下时机重新查询：

- 首次显示。
- 用户切换 6、12、24 小时。
- 收到 `GlucoseStore.glucoseSamplesDidChange`。
- App 回到前台且历史页面仍可见。

连续收到多次变更通知时只保留最后一次刷新结果，避免旧查询覆盖新数据。

页面显示时注册 glucose store 和前台通知，离开页面时注销；页面退出后不得继续查询或更新状态。

## 状态与错误

| 状态 | 页面行为 |
|---|---|
| 加载中 | 图表区域显示进度状态，保留 segmented control |
| 有数据 | 显示图表和明细 |
| 所选范围没有数据 | 显示 `No glucose data in this period` |
| 查询失败 | 显示简短错误和重试按钮 |
| CGM 被删除 | 返回首页后隐藏历史按钮；已打开页面允许查看 Loop 中已有历史 |
| 历史补包仍在进行 | 先显示已有数据，收到新数据后自动刷新 |

## 与 MicroTech LinX 的关系

- 直接连接模式保留现有当前值通知和历史补包逻辑。
- 历史页面不主动要求 MicroTech 重新连接。
- 如果直接连接已经补回 24 小时数据，页面立即显示完整 24 小时。
- 如果设备只返回部分历史，页面只显示 Loop 实际收到并保存的数据。
- 广播模式仍只接收实时广播，不承诺补齐 6、12 或 24 小时历史。
- 官方 App 与 LinX 的蓝牙连接冲突不由历史页面处理。

## 测试

### 单元测试

- 默认范围是 6 小时。
- 6、12、24 小时分别使用正确的查询起点。
- 查询结束时间使用当前时间。
- 图表数据按时间正序。
- 明细数据按时间倒序。
- 图表和明细的数据条数与 `GlucoseStore` 查询结果一致，页面不二次去重。
- 切换范围后旧查询结果不能覆盖新结果。
- 收到 glucose store 变更通知后刷新当前范围。
- 连续收到变更通知时，迟到的旧查询结果不能覆盖最后一次结果。
- App 回到前台时刷新当前范围。
- 页面退出后注销通知，不能继续触发查询或状态更新。
- 空结果和查询错误进入正确状态。
- 单位切换后血糖显示文本更新。

### 页面与导航测试

- 配置 CGM 后首页状态区下方显示历史入口。
- 没有 CGM 时首页隐藏历史入口。
- 历史入口不改变首页导航栏隐藏状态、Glucose 曲线点击行为和底部工具栏布局。
- 点击入口打开带返回按钮的 `Glucose History` 页面。
- 页面存在 `6 Hours`、`12 Hours`、`24 Hours` 三个 Tab。
- 默认选中 `6 Hours`。
- 切换 Tab 后图表和明细同时更新。
- 6、12、24 小时横轴分别使用 1、2、4 小时标签间隔。

### 构建与真机验证

- `MicroTechCGM` 现有测试继续通过。
- 新增 Loop 历史页面测试通过。
- `LoopWorkspace` generic iOS 构建通过。
- 真机签名构建、安装和启动通过。
- 使用 LinX 直接连接验证历史补包写入后，6、12、24 小时页面能自动刷新。
- 页面只显示真实写入 `GlucoseStore` 的数据，不使用测试或模拟值。
- iPhone XR 竖屏下 6、12、24 小时横轴标签均不重叠，图表、明细和顶部选择器不互相遮挡。

## 完成标准

1. 首页存在可访问的血糖历史入口，未配置 CGM 时隐藏。
2. 页面支持 6、12、24 小时三个 Tab，默认 6 小时。
3. 图表和明细读取同一批 `GlucoseStore` 数据。
4. 历史补包入库后页面自动刷新。
5. 页面不复制或修改 MicroTech 历史数据。
6. 页面不影响现有预测页面、治疗计算和 CGM 连接流程。
7. 自动化测试、构建和真机验证全部通过。
